# 台架缺口的内存与 IO 维度实测 · 预注册（2026-11-11，跑分前冻结）

承接 2026-11-03 篇第 5 节未解问题与选题池第 6 条：纯 CPU 负载至
1.5 倍超订只造出最高 9.69 个点缺口、复现不了 2026-10-28 的
29.8%。本轮同构设计：链路、注入参数、判定线全部冻结，只把操纵
变量换成可用内存与磁盘 IO 两维，量台架缺口 gap 在两维上是否在
某档跳变，并与 CPU 档的门槛形态（满核及以下为零、超订才常态
出现）对照。

## 受控设置（跑分前冻结）

- 链路与 2026-10-28/11-03 轮逐项相同：traffic_gen → fault_proxy
  → 额外丢弃垫片（q=0，只计数不丢）→ echo_server，本机回环。
  注入参数逐字不变：loss 0.20 双向、delay 40 ms、jitter 30 ms、
  flap 0.6/2.5、代理种子 1234；流量 sustained 2000 pps × 5 s
  = 10,000 包、收尾宽限与前作同。垫片种子基数 61000。
  无 CPU hog（本轮 CPU 不是操纵变量；逐轮 loadavg 照常记录）。
- 基线可用内存 MA0：bench 启动时 /proc/meminfo 的 MemAvailable
  连取 5 次（间隔 1 s）的中位数，落盘记录。立项时人工采样
  622–672 MB（本机 8 GB、无自设 swap 扩展、与他线共用主机，
  基线本身已低——如实记为本轮画像的一部分）。
- 内存臂（MEM）四档，以驻留触摸内存量定档：M0=0、M1=0.5×MA0、
  M2=1.0×MA0、M3=1.6×MA0（绝对上限 1000 MB）。内存 hog 为自有
  Python 进程：分配 bytearray 后逐页写入触摸、随后循环逐页
  重触摸保活（不烧 CPU 成环等待、每轮重触摸间 sleep）。
  安全护栏（跑分前定死）：采样线程每 0.25 s 读 MemAvailable，
  若连续 2 次低于 120 MB，立即杀 hog 并在本轮记录记
  guard_killed=true，该轮不删、按无 hog 继续跑完并在正文披露；
  hog 在每档首轮前启动、预热（分配＋全量触摸完成并稳 2 s）后
  才开跑，该档跑完杀掉。
- IO 臂（IO）四档，以同步写进程数定档：I0=0、I1=1、I2=2、
  I3=4。每写手一个独立文件（位于本项目 data 的 iohog 工作文件，
  跑后删除），循环做 4 KB 追加写 + fdatasync，只写自有文件、
  不碰链路文件。立项实测本机 fdatasync 单次平均 22.1 ms
  （20 次样本）——磁盘本身慢且忙（立项时 PSI io full
  avg10 约 28%），如实记为本轮画像。写手在每档首轮前启动、
  预热 2 s，该档跑完杀掉并汇总各自完成的同步写次数。
- 每档 4 次重复，两臂共 32 轮。档位顺序 M0→M3 后 I0→I3 不随机
  （与 2026-11-03 同妥协：靠逐轮 loadavg/PSI/压力源读数对账，
  不许把顺序效应冒充操纵效应）。
- 每轮记录：全链六跳计数、exporter collect() 回读的 L 与五量、
  轮前 loadavg、轮内 MemAvailable 采样（0.25 s 间隔，记最小与
  中位）、轮前后 PSI memory/io 的 some/full total 增量（µs）、
  /proc/vmstat 的 pgscan_kswapd/pgsteal_kswapd/pswpin/pswpout
  增量、系统级 UDP RcvbufErrors/InErrors 增量、压力源实际量
  （内存 hog 目标 MB 与护栏事件；IO 写手完成同步写次数）。

## 量法（跑分前定义，与前作同）

- gap = 1 − in_client / sent；L 为 exporter 总丢包（部署口径）；
  L_iso 为以 in_client 为分母的隔离口径；OLD 判定 L > 0.75。
- D = 1 − in_server / F_c，F_c = forwarded − echoed；CAND 线
  D > 0.10。抖动份额与前作同口径。
- 顶线所需缺口 g*：以本轮 M0＋I0 两组合池 L_iso 均值为注入
  基线，解 1 − (1−g)(1−L_iso) = 0.75（解析层，非实测）。
- 操纵检验（manipulation check）：PSI 增量须随档位动——内存臂
  看 PSI memory full 增量、IO 臂看 PSI io full 增量；某档压力
  指纹不动，该档的零结果只许读作「压力没加上」，不许读作
  「该维度无害」。

## 预注册预测（跑分前写死，错了在正文公开认）

P1 内存臂单调：四档 gap 中位数非递减（允许 M0/M1 并列为零）。
P2 安静复现：M0 与 I0 共 8 轮 gap 全部 ≤ 0.02。
P3 内存阈值：M3 档 gap 中位数 ≥ M0 中位数 + 0.02（2 个点）——
    1.6×MA0 的驻留压力把可用内存压进回收/换页区，接收循环
    被缺页与回收停顿成批饿住，缺口在最高档出现。
P4 IO 梯度：IO 四档 gap 中位数非递减，且 I3 中位数 ≥ I0
    中位数 + 0.01（代理逐轮迭代末尾 flush 决策日志、链路组件
    均有文件 IO，同步写压力把停顿传进接收循环）。
P5 机制归属：凡 gap 中位数 > 0.005 的档位，该档 RcvbufErrors
    增量合计 ≥ 该档全链六跳缺口包数合计的 50%。
P6 分解免疫：32 轮 D 全部 ≤ 0.03（与 CPU 臂同结论的跨维度
    复验）。
P7 误报侧：32 轮无一轮 OLD 触发（L ≤ 0.75）。
P8 操纵检验：M3 每轮 PSI memory full 增量中位 ≥ M0 的 3 倍；
    I3 每轮 PSI io full 增量中位 ≥ I0 的 3 倍。

## 不许做的事

- 不许跑分后改档位定义、判定线（0.75 / 0.10）或 gap 定义再重报。
- 不许删轮：护栏杀 hog、恒等式不成立、缺口异常的轮次全部留账
  单独说明。
- 内存 hog 只许压到护栏线即停手；不许为凑数据关护栏、不许
  动系统级 vm 参数、不许用 swapoff/mount 等系统级手段。
- 结论只许对本机画像（8 GB、基线 MemAvailable 约 0.6 GB、
  fdatasync 约 22 ms、与他线共用主机）说，不许外推成内存/IO
  的全称规律。
