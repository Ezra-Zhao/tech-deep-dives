# 三维合压把缺口推到 56.6 个点，还顶穿了告警线：台架缺口的组合因子与突发脉冲实测

作者：Guangyi Zhao

## 1. 问题与背景

台架缺口的旧案查到第四篇了。2026-10-28 量注入带告警时，发生器发出 10,000 个包、进入代理的时少时多，第一跳缺口 gap = 1 − in_client/sent 在 28 轮里从 0 漂到 29.8%，大到能左右告警结论。之后两轮受控实验逐维排除：2026-11-03 的 CPU 一维，6 个 hog 在 4 核上 1.5 倍超订，缺口中位 3.99 个点、最大 9.69 个点；2026-11-11 的内存与 IO 两维，驻留 1000 MB 的最大缺口只有 0.46 个点，4 个同步写手逐轮为零。三维单打，没有一维接近 29.8%。

这一篇还最后两笔账：三维同时压到各自已测的最高档，缺口能不能被推到 20 个点以上；同样的压力改成突发脉冲——只在每轮 5 秒流量的前 2 秒在场——形态会不会不一样。设计、判定线与六条预测在跑数前冻结落盘（data/2026-11-23-combo-pulse-prereg.md），链路、注入参数、量法与前三篇逐项相同：发生器 → 故障代理（双向丢 20%、延迟 40 加抖动 30 毫秒、抖动窗 0.6/2.5、种子 1234）→ q=0 计数垫片 → 回声服务器，2000 pps 乘 5 秒共 10,000 包。

结论先行：组合不是三维取大，是真叠加。组合持续臂四轮缺口 8.70 / 14.33 / 56.58 / 8.96 个点，中位 11.65 个点，约 CPU 单维中位的 2.9 倍；其中一轮缺口 56.58 个点，不但越过 29.8% 的旧案纪录，还越过本轮解析出的顶线所需缺口 g*＝45.69 个点——那一轮总丢包 L 读回 1.0，注入带告警的 0.75 线被实测顶穿，这是四篇里第一次。脉冲形态则明显弱：组合脉冲中位 3.45 个点，CPU 单维脉冲中位 5.79 个点，都低于持续形。我跑分前写死的六条预测里，P1（组合到不了 29.8%）和 P6（分解免疫、不顶线）当场阵亡，细节在 3.5 节认账。

## 2. 方法

- 四臂各 4 轮，共 16 轮，臂序 C0→C1→C2→C3 不随机（与前两轮同妥协，靠逐轮 loadavg/PSI/压力源读数对账）。C0 无压力基线；C1 组合持续：6 个纯 CPU hog ＋ 内存 hog 驻留 1000 MB ＋ 4 个同步 IO 写手（4 KB 追加写加 fdatasync），全程在场——三项分别是前两轮各自的最高档；C2 组合脉冲：与 C1 完全相同的三源，在发生器启动时刻点火，t=+2.0 秒全部杀停，后 60% 无压力跑完；C3 CPU 脉冲：只有 6 个 CPU hog，同样的 2.0 秒点火窗，用来隔离脉冲形态是否 CPU 一维就能解释。
- 一处方法差异先声明：前两轮压力源按档启动、整档共用；本轮脉冲臂必须逐轮点火/杀停，故全部压力臂改为逐轮启动，每轮预热（内存 hog 分配触摸完成并稳 2 秒、IO 写手 2 秒、CPU hog 2 秒）后才发流量。C1 每轮拿到的是新鲜预热的压力，与前轮整档共用的稳态压力不完全同构，记入第 5 节局限。
- 安全护栏沿用 2026-11-11 定版：采样线程每 0.25 秒读 MemAvailable，连续两次低于 120 MB 立即杀内存 hog、该轮留账披露；内存 hog 绝对上限 1000 MB；不动任何 vm 系统参数。本轮 16 轮护栏零触发。
- 每轮记录：全链六跳逐向计数、exporter 真实 collect() 回读的 L 与重构 D 所需五量、轮前 loadavg、轮内带时间戳的 MemAvailable 采样、轮前后 PSI cpu/memory/io 停顿增量、/proc/vmstat 回收增量、系统级 UDP RcvbufErrors 与 InErrors 增量、IO 写手每轮完成的同步写次数、脉冲关断实测时刻。
- 本轮主机画像必须先交代，因为它比前两轮都差：立项时 MemAvailable 约 1.0–1.2 GB，bench 启动实测 MA0 已回到 1,926,964 KB（约 1.88 GB）；C0 基线轮的轮前 loadavg 最高 9.43、往返时延 p99 中位 281.1 毫秒（2026-11-11 同口径约 137–141 毫秒），系统级 PSI cpu some 增量中位高达 7.83 秒——这台与多条生产线共用的主机在本轮窗口里本身就忙。基线缺口仍守在 0.77 个点以内（见 3.1），但所有绝对数字只许对这个画像读，第 5 节再记一笔内存基线在轮次间漂移的账。

## 3. 实测数据

### 3.1 总账：组合臂逐轮非零，基线只漏了一次 77 个包

| 臂 | 压力 | gap 四轮（百分点） | 中位 | L 范围 | L_iso 均值 | D 最大 |
|---|---|---|---|---|---|---|
| C0 | 无 | 0.77 / 0 / 0 / 0 | 0 | 0.5343–0.5567 | 0.5397 | 0 |
| C1 | 三维持续 | 8.70 / 14.33 / 56.58 / 8.96 | 11.65 | 0.5909–1.0000 | 0.6801 | 0.9243 |
| C2 | 三维脉冲 2.0 s | 0.92 / 1.98 / 4.92 / 5.60 | 3.45 | 0.5543–0.5930 | 0.5562 | 0.0599 |
| C3 | CPU 脉冲 2.0 s | 6.77 / 4.81 / 0 / 15.20 | 5.79 | 0.5362–0.6242 | 0.5509 | 0.0133 |

C0 唯一非零的一轮漏了 77 个包，系统 RcvbufErrors 增量正好 77，逐包对上——主机虽忙，安静基线的形状没变。C1 则逐轮非零、且没有一轮是小数目：最小 8.70 个点，已经接近 CPU 单维的历史最大 9.69 个点。注入基线自己也被组合压力抬动了：C1 的 L_iso 均值 0.6801，比 C0 的 0.5397 高了 14 个点，去程抖动份额合池从基线的 24.2% 涨到 28.6%——与 CPU 篇「决策时刻被调度滞后糊住」的指纹同形，但幅度大得多。脉冲两臂的 L_iso（0.5562 / 0.5509）只比基线高 1–2 个点，压力撤走后代理的节律基本恢复。

### 3.2 C1-r3：缺口 56.58 个点的一轮，链路是塌掉的，不是一次大号漂移

四轮里最扎眼的是 C1 第三轮，必须单独说清，不能只当一个最大值引用。这一轮：发生器发出 10,000 包，进代理 4,342 个（第一跳缺 5,658 个），代理只转发 2,390 个，服务器只收到 181 个；发生器在收尾宽限内收到的回声是 0 个，exporter 读回 L＝1.0。系统 RcvbufErrors 这一轮增量 6,217，比第一跳缺口还多——接收缓冲溢出不止发生在第一跳。这一轮的 D 按冻结公式算出 0.9243，但这个数字不能按「分解失效」读：D 的分母 F_c＝forwarded − echoed 用的是发生器实收回声数，回声为零时 F_c 被撑成 2,390，D 失去原义。它证明的是回程在窗口内整体没回来——是丢光了还是迟到超过宽限，本轮数据分不开（如实记为未解，见第 5 节）。剔除这一轮，C1 其余三轮中位 8.96 个点，结论「组合中位约 9–12 个点」不依赖这轮撑；但「顶线能被实测顶穿」这一条恰恰只由这轮成立，也不许删——预注册写死了不删轮。

### 3.3 机制归属：缺口开始向下游跳蔓延，接收缓冲仍是大头

六跳逐向对账（四轮合计缺口包数）：

| 臂 | 第一跳 | 代理→垫片 | 垫片→代理 | 代理→发生器 | 六跳合计 | RcvbufErrors 合计 | 占比 |
|---|---|---|---|---|---|---|---|
| C0 | 77 | 0 | 0 | 0 | 77 | 77 | 100% |
| C1 | 8,857 | 559 | 819 | 143 | 10,378 | 8,851 | 85% |
| C2 | 1,342 | 197 | 354 | 4 | 1,897 | 1,897 | 100% |
| C3 | 2,678 | 0 | 101 | 0 | 2,779 | 1,493 | 54% |

与 2026-11-11 篇「191 个跳次全零、只有第一跳缺过」对照，本轮组合压力下缺口第一次蔓延到下游跳：C1 的垫片→代理方向缺了 819 个包、代理→垫片缺 559 个。也就是说饿死的接收点从代理入口扩散到了垫片与回程。但归属大头没变：四个臂的 RcvbufErrors 合计占六跳缺口合计的 54%–100%，逐轮看则方差很大（C1 第四轮缺 896 个包、RcvbufErrors 只增 282；C3 第四轮缺 1,520 个包、只增 252）——系统级计数含其他进程噪声、也漏掉一部分落在别处的溢出，合池达标、逐轮不许硬对，这是 P5 的真实成色。

### 3.4 脉冲臂：关断时刻与内存回收都验到了，缺口按覆盖时长打折还不止

操纵检验全部通过：C2/C3 八轮的实测关断时刻落在 2.002–2.066 秒（预注册窗口 2.0±0.5 秒）；C2 每轮关断后段的 MemAvailable 中位都高于点火段（如第一轮 3,836,432 KB → 4,924,954 KB），内存 hog 被杀后内存确实回来了；C2 的 PSI io full 增量中位 19,010 µs，低于 C1 的 53,903 µs；C1 的轮内 MemAvailable 最低点中位 945,698 KB，比 C0 的 1,735,832 KB 低约 772 MB，PSI io full 是 C0 的约 14.7 倍——压力加上了，不是没加上。

形态结论有两层。第一，脉冲确实弱于持续：组合脉冲中位 3.45 个点，只有持续形的约三成，与 40% 的覆盖时长大体同阶。第二层出乎我预料：CPU 单维脉冲（C3）中位 5.79 个点，反而高于组合脉冲（C2）——但 C3 四轮是 6.77 / 4.81 / 0 / 15.20，方差极大，中位由两轮撑着；C2 是 0.92 / 1.98 / 4.92 / 5.60 的稳步爬升。4 轮的小样本下我只敢说「没看到组合脉冲强于 CPU 脉冲的证据」，不敢反过来说 CPU 脉冲更强。C2 的 D 最大 0.0599（第三轮）越过了前三篇一直守住的 0.03 噪声带——没到 0.10 的 CAND 线，但「分解对压力形态免疫」这句话从这轮起要加限定词了。

### 3.5 预注册对账

- P1 组合不到顶线：**错（半对半错）**。中位部分对了（11.65 < 20 个点），最大值部分错了：56.58 个点越过 29.8%，也越过 g*＝45.69 个点。我跑分前写的理由是「三维的饿死窗口不天然对齐、叠加像取大」——实测中位确实只有单维最大中位的约 2.9 倍、不是三维相加，但尾部不是取大，是塌链。
- P2 安静复现：**对**。C0 四轮全部 ≤ 0.02（最大 0.77 个点）。
- P3 组合可检出：**对**。C1 中位 11.65 个点 ≥ C0 中位 + 1 个点，且逐轮非零。
- P4 脉冲居中：**对**。C0 中位 0 ≤ C2 中位 3.45 ≤ C1 中位 11.65（个点）。
- P5 机制归属：**对（合池口径）**。C1/C2/C3 三个达标臂的 RcvbufErrors 合计分别占六跳缺口合计的 85% / 100% / 54%，均 ≥ 50%；逐轮方差如 3.3 节所示，不许逐轮硬对。
- P6 分解免疫与不顶线：**错**。C1-r3 的 L＝1.0 顶穿 0.75 线、D 形式值 0.9243（成因见 3.2，不能按分解失效读，但线就是被越过了）；C2-r3 的 D＝0.0599 也越过 0.03 噪声带。

六条里对四条、错两条，而错的两条恰恰是这篇真正的发现：单维实验给出的「顶线顶不穿、分解免疫」两个安全结论，在组合压力下同时失效。

## 4. 分析与取舍

对注入带告警的余量设计，本轮把成立条件收紧了一格。2026-11-03 篇的结论是「纯 CPU 负载（含超订）不足以单独顶线」，2026-11-11 篇添了内存与 IO 两维的单维排除；本轮证明这三条单维结论不能拼成组合结论：三维同场时，缺口中位涨到约 11.65 个点、注入基线 L_iso 被抬高 14 个点、缺口向下游跳蔓延，并且尾部存在链路整体塌掉的轮次。按本轮 C0 基线解析的 g*＝45.69 个点，C1-r3 的 56.58 个点已经越过——也就是说在「主机被多维压力打满」的画像下，台架缺口单独就能把 L 顶过 0.75，告警结论在这一轮里不可信。实务上我给自己留的规矩是：量注入带的那台主机只要同时处在 CPU 超订、内存驻留吃紧、同步 IO 饱和三者同场的状态，量出来的 L 先扣一个「台架可信度」标记，不直接进告警判定；三者只占其一时，前两轮的单维上界（9.69 / 0.46 / 0 个点）仍可作余量参考。

脉冲的结果对「压力形态」这个变量给了个便宜的判断：突发压力造缺口的效率低于持续压力，2 秒点火窗（40% 覆盖）的组合脉冲只拿到持续形约三成的中位缺口。若运维上遇到的是周期性突发负载（定时任务对齐、批量同步写），用持续压力的上界去估缺口余量是保守的、方向没错；反过来用脉冲数据估持续压力就会低估，这条不对称性值得记住。

C3 与 C2 的中位倒挂我不打算在本轮解释。可能的成因至少有三个且互相纠缠：C2 每轮要先花数秒分配 1000 MB 内存，点火时刻的系统状态与 C3 不同；臂序 C3 在最后，主机背景负载在窗口内持续变化（C2 期间 MemAvailable 中位一度升到约 4.9 GB，内存那一维在后半程实际上变轻了）；4 轮样本太小。把倒挂写成「CPU 脉冲强于组合脉冲」会是过度解读，留作下一轮的待验假设。

## 5. 局限与未解问题

- 样本小：每臂 4 轮，C1 的中位被 56.58 的塌链轮显著影响，已在 3.2 节给出剔除后的中位（8.96 个点）对照，但两个数字都建立在 3–4 个样本上，只许读量级，不许读精度。
- 主机画像漂移：本轮窗口内 MemAvailable 从立项约 1.0–1.2 GB、启动 1.88 GB，一路漂到 C2 轮次约 4.9 GB；loadavg 与 PSI 都是系统级读数，含其他生产线的活动。内存维的相对强度因此在后半程被稀释，C2/C3 的脉冲读数是在「内存越来越宽裕」的背景下测的——这是本轮最大的混杂项，靠逐轮 MemAvailable 采样留账，没有消除它。
- 逐轮启动与前轮不完全同构：压力源逐轮新鲜预热（第 2 节已声明），与前两轮整档共用稳态压力的数字（如 CPU 中位 3.99 个点）对照时须记得这一层差异。
- C1-r3 的回声为零到底是「丢光」还是「迟到超过收尾宽限」，本轮分不开：需要给发生器加一个延长的静默收尾观测窗，或在代理/垫片上加逐包时间戳回放，才能把塌链轮拆成丢包与迟到两部分。这是下一轮的第一件事。
- D 在回声为零时失去原义（3.2 节）：分解口径需要一个「回程存活」前置条件，回程存活率低于某线时 D 不许出数——这条要先写进预注册再跑，不许事后补规则。
- 结论只对本机画像（8 GB、与他线共用、基线 loadavg 最高约 9.4 的忙碌主机）成立，不外推成组合负载的全称规律。
