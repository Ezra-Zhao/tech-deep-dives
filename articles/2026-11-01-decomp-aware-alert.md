# 拆开总丢包之后，盲区从四成七缩到一成：分解感知告警实测

作者：Guangyi Zhao

## 1. 问题与背景

2026-10-28 那篇里，我给 net-assurance-lab 的注入带告警 NalFaultLossAboveInjectionBand 量了判别力：注入参数一个字不改，在服务器侧再加一级概率为 q 的额外丢弃，现行规则（端到端总丢包大于 0.75 才报警）的检出临界是 q 约 0.47——活过注入的包要在服务器侧再被吞掉近一半、端到端再叠约 22 个点的丢包，它才第一次有机会响；q 在 0.40 以下的服务器侧故障与完全健康不可区分。同一批数据还暴露了它的归因问题：总丢包把三级丢包搅在一起，部署口径下提前触发的轮次，响的其实是发生器到代理之间的台架缺口，不是服务器。

那篇第 4 节给了一个方向：exporter 本来就发布代理的逐级计数，把「由代理计数推算的期望端到端丢包」与实测端到端丢包作差、差值越线才报警，可能同时保住灵敏度和归因。第 5 节如实标注：这个改法没有实现，它的免疫力是推理而非实测。这篇来还这笔账：实现它，与现行 0.75 规则在同一批 q 网格上同场对照，量三件事——检出临界、对台架缺口的免疫力、归因准确性。

先说一个实现时才发现的约束，它决定了整篇的形状。exporter（src/prom_exporter.py）发布的代理计数是双向合计的：in_client、in_server 分开，但 dropped_loss、dropped_flap、forwarded 都是两个方向加在一起的数，没有「去程放行了多少」这条现成的序列。也就是说，逐级计数有，但不按方向拆。期望丢包没法直接读出来，只能靠恒等式从合计里重构——重构得对不对，本身就是要验的第一件事。

结论先行。重构在 40 轮活体里逐轮对得上账（见 3.1）。候选规则的检出临界落在它自己的判定线 0.10 附近：q 等于 0.10 时 4 轮里触发 1 轮（正压线），q 等于 0.15 与 0.20 以上时全部触发；现行规则在同样档位上要么全哑（留出集 q 等于 0.15、0.30 两档，老规则 8 轮全不响，端到端丢包只有 0.60 与 0.67），要么响的是台架。而候选规则给出的不只是一个响或不响：它读出的段丢弃率 D 与垫片实测丢弃率在 40 轮里有 39 轮逐位相等，唯一不等的那一轮，差额能被该轮一个 145 个包的跳间缺口精确解释（算出 0.0240，实测差 0.0239）。

## 2. 方法

候选规则的定义在跑分前冻结，写在预注册文件（data/2026-11-01-decomp-alert-prereg.md）里，连同判定线与五条预测一起落盘，跑完不许挪线。

只许用 exporter 已发布的五个数：sent、echoed、in_client、in_server、forwarded。由它们重构方向量：

- 回程放行数 F_s 等于 echoed。依据是代理回程放行计数与发生器实收数在既往数据里逐轮全等；本轮每一层都复核这条恒等式，不成立的轮次单独报告。
- 去程放行数 F_c 等于 forwarded 减 echoed（forwarded 是双向合计，减去回程即去程）。
- 回程腿存活率 b 等于 echoed 除以 in_server。
- 期望回声数 E_exp 等于 F_c 乘 b：若去程放行的包全部到达服务器并被回显、只有回程腿按本轮实测存活率再丢，发生器应收到的回声数。期望丢包 L_exp 等于 1 减 E_exp 除以 sent；实测丢包 L 等于 1 减 echoed 除以 sent。
- 段丢弃率 D 等于 1 减 in_server 除以 F_c。它量的那一段是：从代理去程放行计数点出发，经垫片去程、服务器、垫片回程，到代理回程入数计数点为止——两个代理腿之外的整段。代数上 D 与期望差同源：L 减 L_exp 等于 D 乘 E_exp 除以 sent，只是尺度不同；判定用 D，因为它的真值就是那一段的丢弃率，可以直接对账。

判定线冻结为 D 大于 0.10。选 0.10 的理由在跑分前写明：它须高于段内跳间缺口的噪声量级（2026-10-28 全网格只见过一轮 145 个包的代理到垫片缺口，约占该轮 F_c 的 2.7%），又须远低于现行规则约 0.47 的临界；另留 D 大于 0.05 一档敏感性口径只报告、不作主判定。现行规则 OLD 照旧：L 大于 0.75。

三层证据，性质分开标注，不许混着说：

- A 层，存档重评（旧数据、新规则）：2026-10-28 的 28 轮活体全账，q 网格 0 至 0.60 共 7 档、每档 4 次。只用上面五个数重算两条规则；垫片账与代理逐方向账只用来验重构恒等式与给 D 打分，不作规则输入。
- B 层，新活体验证（留出）：同一套真实组件与同一块垫片，注入参数逐字不变（loss 0.20 双向、delay 40 加 jitter 30、flap 0.6/2.5、代理种子 1234，流量 2000 pps 乘 5 秒），额外丢弃种子换新基数 31000，q 取 0、0.15、0.30 三档、各 4 次共 12 轮。这两档非零档在 OLD 的盲区内、在 CAND 的线之上，是两条规则预言相反的档位。规则的五个数全部从 exporter 真实 collect() 输出文本里解析——就是 Prometheus 会抓到的那个对象，不是原始日志。
- C 层，合成扰动（算术、不是实测）：拿 A 层 q 等于 0 与 0.20 的 8 轮计数，人工注入台架缺口 g 取 0.1、0.2、0.3（in_client 与全部下游计数同比例削减，sent 不变——模拟包在发生器到代理一段被台架吞掉、幸存者带着注入自己的存活剖面继续走），重算两条规则。

五条预注册预测（P1 至 P5）的判定在 3.5 节末尾集中对账，错了的当场认。

## 3. 实测数据

### 3.1 重构恒等式：40 轮逐轮对上

A 层 28 轮里，重构的 F_c 与代理日志逐方向账的去程放行计数逐轮全等，28 比 28；F_s 等于 echoed 与回程放行计数逐轮全等，28 比 28；in_server 与服务器回显计数逐轮全等，28 比 28。B 层 12 轮同样三项全等，12 比 12，且 exporter 解析出的丢包率与发生器汇总逐轮全等。恒等式的成立条件值得点名：在这 40 轮里，代理到发生器一段（回程最后一跳）没有丢过一个包。3.4 节与第 5 节会回到这个条件——它是重构的地基，也是这套读法离开回环台架时最先要重验的东西。

唯一的段内噪声事件仍在 A 层：q 等于 0.10 第 2 轮，代理放行之后、垫片入数之前少了 145 个包（代理到垫片缺口），其余 39 轮该缺口为 0。这一轮在 3.3 节单独对账。

现行规则的旧结论在重评里复现：隔离口径 q 到 0.40 仍 0 触发、0.50 全触发，临界约 0.47（2026-10-28 篇解析值 0.4707 与模型插值 0.4705）。候选规则的过渡带就压在自己的判定线上：q 等于 0.10 时四轮 D 三轮在线下（0.0928 至 0.0996）、一轮在线上（0.1227，即 3.1 节那一轮段内缺口轮），q 等于 0.20 起全线越线。也就是说它的有效检出临界约 0.10 至 0.15，是现行规则的约四分之一到三分之一。换成端到端语言（B 层实测）：q 等于 0.15 时端到端丢包只比无注入基线高约 6.9 个点，CAND 已经稳响；OLD 要等端到端再叠约 22 个点。

敏感性口径附带报告：判定线降到 0.05 时，A 层 q 等于 0.10 档变为 4/4，其余各档不变，q 等于 0 档仍 0/4。0.05 不是不可用，只是离段内噪声（单次事件 2.4 个点）只剩一倍余量，0.10 留了约四倍。

### 3.3 归因：D 读出的就是那一段丢了多少

把 D 与垫片自己的实测丢弃率（dropped_extra 除以 in_client，这是真值、不进规则）逐轮对账：A 层 28 轮里 27 轮逐位相等；B 层 12 轮全部逐位相等。合计 40 轮 39 轮精确命中。唯一不等的是 3.1 节那一轮：D 等于 0.1227，垫片实测 0.0988，差 0.0239。而这一轮的段内构成是已知的：145 个包丢在代理到垫片这一跳，按该轮计数折算，它对 D 的贡献是（145 除以 F_c）乘回程段存活份额，约 0.0240——与实测差 0.0239 对齐到小数点后第三位。换言之 D 没有读错：它读的是整段（垫片加这一跳）的丢弃，垫片账只记自己那一级，两者的差正好是那一跳的账。这同时是它的能力边界：D 能定位到段，段内再细分要靠段内计数，而 exporter 没有发布段内计数。

对名义 q 的误差账（含量子化与垫片自身抽样涨落）：A 层 28 轮绝对误差中位数 0.0038、最大 0.0227（即上面那轮）；B 层 8 个非零轮误差在负 0.0095 到正 0.0077 之间。由于 D 与垫片实测逐位相等，D 的轮间散布就是垫片伯努利抽样的散布本身：F_c 约 5500 至 6100 时 q 等于 0.15 的抽样标准差约 0.0048，B 层四轮 D（0.1452、0.1497、0.1470、0.1577）的散布与之同量级。

台架免疫的正面证据在 A 层那两轮旧规则被顶线的轮次里。q 等于 0.20 第 2 轮：台架缺口 29.8%，总丢包 0.7655 越线，隔离口径 0.6658 其实没到线，它响的是台架；同一轮 D 等于 0.2057，对真值误差 0.0057。q 等于 0.30 第 4 轮：台架缺口 21.8%，总丢包 0.7693 越线；D 等于 0.3066，误差 0.0066。两轮里总丢包被台架抬高了约 7 到 10 个点，D 的误差都停在 0.007 以内。全 28 轮的相关账：台架缺口率与总丢包中台架贡献部分的 Pearson 相关 0.9635，与 D 误差的相关负 0.0914——前者是搅动总丢包的那只手，后者基本不碰 D。机制上不意外：台架丢的包根本进不了代理，F_c 与 in_server 同比例缩小，比值不动；总丢包的分母 sent 不缩，所以它全额承受。

### 3.5 C 层与预注册对账

C 层 24 次扰动（8 轮乘 3 档 g）：D 的变化量最大值 0.0——在计数取整精度内纹丝不动，这是比值构造的必然，算术层只确认没有实现错误。OLD 侧：q 等于 0.20 的四轮在 g 等于 0.3 时 L 从 0.6838 至 0.7655 升到 0.7787 至 0.8358，触发由 1/4 变 4/4；q 等于 0 的四轮在 g 等于 0.3 时 L 最高只到 0.6767，没有越线。

预注册五条预测对账：P1（A 层 q 等于 0 四轮 D 不超过 0.03）命中，实测全为 0.0000。P2（q 不小于 0.20 各档 CAND 4/4、q 等于 0.10 为临界档、OLD 隔离口径旧结论复现）命中。P3（误差中位不超过 0.02；两轮台架顶线轮的 D 仍在真值正负 0.03 内）命中，中位 0.0038、两轮误差 0.0057 与 0.0066。P4（B 层 0.15 与 0.30 两档 CAND 4/4、OLD 0/4）命中。P5 前半（C 层 D 变化不超过 0.005）命中，实测 0.0；后半（g 等于 0.3 时 q 等于 0 轮次被 OLD 顶过线）未命中——我预注册时把台架顶线所需缺口估低了：从 q 等于 0 基线出发顶过 0.75 需要约 47.1% 的缺口（2026-10-28 篇 3.5 节算过这个数，我冻结预测时没有回查它），g 网格上限 0.3 不够。这一条是我的预测错，不是数据错；它反而再次确认了旧规则在纯台架方向上的余量，并提醒：预注册写预测之前先回查自己上一篇算过的数。

## 4. 分析与取舍

把两条规则的性格并排：现行规则问的是「总丢包是否超出注入能解释的上限」，它的输入只有一个总数，所以它的临界被注入带宽（约 52.8% 的基线到 75% 的线）与台架噪声一起决定，响了也不知丢在哪。候选规则问的是另一个问题：「两个代理计数点之间那一段，丢包率是否异常」。它的判定量是本轮实测的比值，注入参数的涨落、注入带宽、发生器到代理一段的台架丢包，在构造上都不进这个比值——所以临界能压到 0.10，响的同时还给出丢了多少（读数即估计，典型误差在 1 个点内）与丢在哪一段。上一代价换来的三样东西，这一代价是：它的世界只有一段。若丢包发生在代理腿上（注入本身变重）或发生器到代理一段，它一个字都不会说；它必须与原来的带告警并联部署，不是替换。这也是预注册里就定死的部署口径：CAND 管段外丢包，OLD 管总量异常，两条各守一段账。

判定线 0.10 的取舍再摊开一次。它下方的噪声证据目前只有两条：段内跳间缺口的单次实测事件（2.4 个点）与抽样散布（约半个点）。0.10 是单次事件的约四倍，0.05 是约两倍。在这台回环台架上 0.05 也没出过事，但真实链路里段内每一跳的缺口分布没有先验上界，把线压到噪声的两倍处，等于把误报率押在「不会出现比见过的再大一倍的缺口事件」上。我选 0.10 而不是 0.05，丢掉的是 q 在 0.05 到 0.10 之间的段丢弃检出（端到端约 2 到 5 个点），换的是四倍于已见噪声的余量；哪天段内计数补齐、能把缺口与真丢弃分开，这条线还可以再往下挪。

落到 PromQL 上，CAND 不需要 exporter 改任何东西，五个数现成：D 写成表达式即 1 减（in_server 除以（forwarded 减 echoed）），配上与现行规则相同的 for 语义即可。仍要沿用 2026-10-24 以来的提醒：这个 exporter 发布的是已完成运行的快照，for 量的是坏数据被连续抓取的时长、不是网络状态的持续时长；把本篇的判别力结论搬进流式 exporter 场景，检出延迟要另算。

最后留一句给「作差」这个提法的原始形态：预注册里我同时定义了 L 减 L_exp（期望丢包差）与 D。两者同源，但只有 D 的真值可直接对账、临界不随注入基线漂移；L 减 L_exp 更像给人看的端到端翻译（例如 q 等于 0.20 第 2 轮，L 等于 0.7655、L_exp 等于 0.7048、差 0.0607 个端到端点）。正文判定全程用 D，L_exp 只在这一段出现，不两处下结论。

## 5. 局限与未解问题

- 全部活体证据来自本机回环与这一台主机。B 层 12 轮台架缺口为零，免疫力证据靠 A 层重评（缺口最高 29.8% 的真实轮次）加 C 层算术；换一台更忙的主机或真实网络，段内缺口的分布要重新量，0.10 这条线要按新分布重定。
- D 的地基是恒等式 F_s 等于 echoed，即代理回程放行到发生器计数之间不丢包。40 轮里它逐轮成立，但那一段在回环台架上几乎不可能丢包；部署到真实路径时，这段若有丢包，会被折进 F_c 的重构误差里（F_c 被低估、D 被高估），方向是偏误报。本轮没有给这一跳注入丢包做对照，这是最先欠着的一笔。
- D 只定位到段：垫片丢弃、服务器丢弃、段内各跳缺口在 D 里不可分（3.3 节那 0.0239 就是一跳缺口冒充段丢弃的实证，只是那次它小且可解释）。要再细分，exporter 需要发布段内计数或逐方向的代理放行数——那是改 exporter 的事，本篇的全部意义恰恰是先证明不改 exporter 能走多远。
- D 对回程方向的段丢弃是盲的还是敏感的，没有实测：本轮垫片只丢去程。按计数点位置推，服务器回程经垫片回程段回到 in_server 计数点，这一段的丢弃会抬高 D 并被记在整段账上——这是推理，不是实测；垫片改丢回程的对照轮在选题池里另有条目（回程丢弃对照实测），与本篇的未解问题合并处理。
- 每档仍只有 4 次重复，触发率分辨粒度 25 个点；临界附近（q 等于 0.10）的过渡形状靠 D 读数本身的位置判断（四轮读数贴着线分布），没有加密网格。D 的抽样散布由垫片计数直接给出逐轮真值对账，比触发率计数硬，这是本篇敢用 4 次重复下结论的依据，但加密 q 在 0.05 至 0.20 一段的触发曲线仍值得一测。
- P5 后半未命中已在 3.5 节认账：预注册预测与自己上一篇的既有计算（纯台架顶线需 47.1% 缺口）不一致，冻结前未回查。这个过程教训与数据结论分开记，不影响 A、B 两层的实测账。
