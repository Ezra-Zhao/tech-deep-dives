# 阈值不是常数，是距离的函数：面积阈值检测器的标定漂移实测

作者：Guangyi Zhao

## 1. 问题与背景

上一篇测 Bloom-Counter 时，我在局限里留了一句没兑现的话：面积拆分用的单位面积取自同批场景，跨拍摄距离必须重新标定，而我没有验证过这个迁移。这篇就是来还这笔账的，而且还完之后发现，要重标的远不止一个数。

先把检测器的家底摆出来。`detector/color_segmentation.py` 里写死了三个绝对像素参数：连通域面积小于 `min_area=120` px² 的直接当噪声扔掉；面积达到 `bloom_area_min=900` px² 的记开花、不到的记花苞；形态学闭运算和开运算的核是 7 px。这三个数都是在 1280×960、某个固定机位下调出来的。教科书会告诉你：相机离远一倍，目标在画面上的线尺寸减半、面积变四分之一，所以面积阈值按距离比的平方缩放就行。这句话对不对、对到哪一步、漏了什么，是本文要量的三件事：

1. 什么都不改，同一场景拍远了会怎么坏、按什么顺序坏；
2. 只按平方律缩放两个面积阈值，能修到什么程度，修不动的地方卡在哪；
3. 「分辨率变低」和「距离变远」是不是同一件事——现场最常见的说法是把两者混着讲，换了台低分辨率相机就急着重标阈值，这个动作到底有没有必要。

## 2. 方法

场景与评分沿用上一篇：仓库自带模拟器生成 4 张 1280×960 场景（种子 101/202/303/404），合计 210 个目标（开花 134、花苞 76），逐个中心匹配、类别必须一致才算命中，分开报告开花召回与花苞召回，4 张场景微平均。匹配容差在图像自身坐标里取 max(38·s，1.1×半径)，s 为该图的几何缩放比，保证各缩放档的相对容差一致。基线自检：原始图上 precision = recall = F1 = 1.000，与上一篇一致。检测器本体不改，三个参数通过构造器注入不同取值。

实验分两部分，两部分的区别是刻意分开的：

- A 组（几何缩放，模拟距离变化）：整图用 INTER_AREA 缩到 1280·s × 960·s，真值中心与半径同步乘 s。s 取 1.0 / 0.8 / 0.65 / 0.5 / 0.4 / 0.3 / 0.22。换成距离语言：s=0.5 相当于同一台相机退到两倍远（一帧覆盖四倍面积），s=0.22 约为 4.5 倍远。每档测三种参数策略：A1 全部固定（120 / 900 / 核 7）；A2 两个面积阈值按 s² 缩放、核固定 7；A3 面积阈值按 s²、核按 7·s 取奇数（下限 3）一并缩放。另对每档做一轮阈值扫描：`bloom_area_min` 在理论值 900·s² 的 0.25 至 1.3 倍之间取 8 个点，看最优阈值到底落在哪。再加一组单参数消融：每档分别只缩放三个参数中的一个，拆清固定参数的失败由谁贡献。面积漂移另有直接测量：复刻检测器内部管线（HSV 掩膜加形态学）提取全部轮廓，按真值中心匹配后统计每类轮廓面积中位数，与 s² 预测值对比。
- B 组（分辨率退化，几何不变）：整图先 INTER_AREA 缩小到 r 倍、再 INTER_LINEAR 放大回 1280×960，真值不动。r 取 1.0 / 0.5 / 0.33 / 0.25 / 0.167 / 0.125，最低档的有效像素只剩 160×120。测固定参数一组，并同样扫一轮 `bloom_area_min` 倍率。

原始数据与脚本：`data/2026-10-20-bloom-scale-bench.json`、`data/2026-10-20-bloom-scale-bench.py`，消融脚本与结果在 `data/2026-10-20-bloom-scale-ablation.py` 与同名 JSON 里，仓库自带虚拟环境一条命令可复跑。

## 3. 实测数据

### 3.1 什么都不改：失效是分阶段来的，先撞噪声地板，再撞分类门槛

| s（约合距离） | A1 固定参数 F1 | 开花召回 | 花苞召回 | 总数误差 |
|---|---|---|---|---|
| 1.0（基准） | 1.000 | 1.000 | 1.000 | 0.0% |
| 0.8（1.25×） | 1.000 | 1.000 | 1.000 | 0.0% |
| 0.65（1.5×） | 0.931 | 1.000 | 0.645 | -12.9% |
| 0.5（2×） | 0.402 | 0.515 | 0.000 | -36.7% |
| 0.4（2.5×） | 0.082 | 0.104 | 0.000 | -36.7% |
| 0.3（3.3×） | 0.012 | 0.015 | 0.000 | -38.1% |
| 0.22（4.5×） | 0.000 | 0.000 | 0.000 | -51.9% |

s=0.8 时毫无感觉，这不是参数稳健，是余量大：基线图上开花轮廓面积中位数 3,806 px²、花苞 343.8 px²，两类相距 11 倍，分类门槛在 630 到 1,170 之间任意取（理论值 900 的 0.7 至 1.3 倍）都是满分。门槛离两类都远，距离动一点，什么都不会发生——这个「没事」最容易骗人。

真正的失效是分阶段来的，消融拆得很干净（表中为 F1）：

| s | 只缩放 min_area | 只缩放 bloom 门槛 | 只缩放核 | 两阈值都缩放（A2） | 全缩放（A3） |
|---|---|---|---|---|---|
| 0.65 | 1.000 | 0.931 | 0.934 | 1.000 | 1.000 |
| 0.5 | 0.692 | 0.776 | 0.401 | 0.998 | 1.000 |
| 0.4 | 0.300 | 0.776 | 0.064 | 0.915 | 1.000 |
| 0.3 | 0.018 | 0.765 | 0.000 | 0.768 | 1.000 |

第一阶段（s=0.65）坏的只有 `min_area`：开花召回仍是 1.000，花苞丢了三分之一。花苞缩到中位面积 132 px² 一带，固定 120 的噪声地板开始把真花苞当噪声删；只把这一个数按 s² 改对，F1 直接回满分，其余两个参数动不动无所谓。第二阶段（s=0.5）轮到分类门槛：只改 `min_area` 时花苞召回回 1.000、开花召回停在 0.515——开花面积中位数已缩到 913 px²，约一半开花跌破固定的 900 被改判成花苞；反过来只改分类门槛时开花召回 0.993、花苞召回仍是 0。两个阈值各管一头，缺一个都不行。这一段的失败形态和上一篇光照组里的一样：不是漏检，是类别迁移——s=0.5 固定参数下检出总数只少了 37%（133 个），但按本文口径（类别一致才算命中）命中的只有 69 个；另检出的 64 个一律标成「花苞」，而真值花苞无一命中，这 64 个只能来自被改判的开花连通域或其碎片，没有别处可来。顺带交代一个容易看错的数：s=0.4 时总数误差同为 -36.7%，不是填表笔误——检出总数同为 133 个，但构成已完全不同（69 开花＋64 花苞标 → 14 开花＋119 花苞标）。总数误差纹丝不动、结构已经塌完，这是只看总数会漏掉的又一例。

### 3.2 只缩放面积阈值：到 s=0.5 为止有效，之后再怎么调门槛都没用

A2（两阈值按 s²、核固定 7）在 s=0.65 与 0.8 满分，s=0.5 时 F1 0.998（只丢 1 朵开花），到 s=0.4 掉到 0.915、花苞召回 0.579，s=0.3 时 F1 0.768、花苞召回 0.013，s=0.22 时花苞召回归零、F1 0.750。开花在 A2 下一直很稳（s=0.3 仍有 0.970），塌的只有花苞。

关键证据是阈值扫描（扫描在 A2 家族内做：`min_area` 已按 s² 缩好，只动 `bloom_area_min`）：s=0.22 时从理论值的 0.25 倍扫到 1.3 倍，F1 恒为 0.750，一格不动；s=0.3 时全程只在 0.7625 到 0.7683 之间动 0.006；s=0.4 时门槛升到理论值的 0.55 倍后 F1 停在 0.9147 的平台上，再往上扫到 1.3 倍不变（往低处扫到 0.25 倍反而更差，那是把幸存花苞也改判成开花的另一头）。三档共同的形态是：剩余损失全部在花苞召回上（0.579 / 0.013 / 0.000），且与门槛取值无关——丢失发生在分类之前，花苞根本没有走到分类器面前。这与上一节消融里「只缩放 bloom 门槛」能把 s=0.4 的 F1 从 0.082 拉到 0.776 不矛盾：那组消融里 `min_area` 是固定的，拉起的是开花那一头（开花召回回到 0.993、花苞召回仍是 0）；两个实验动的变量不同，救的也不是同一批目标。直接量轮廓也证实了这一点：核固定 7 时，能按中心匹配到的花苞轮廓数从基线 76 个掉到 s=0.5 的 76、s=0.4 的 44、s=0.3 的 1、s=0.22 的 0。花苞是椭圆，短轴全宽约 1.1×半径：s=0.4 时约 4.8 至 7.5 px，与 7 px 的开运算核正好临界；s=0.3 时约 3.6 至 5.6 px，整体小于核，开运算直接把掩膜抹掉。这不是阈值问题，是一个以像素为单位的长度参数在缩放下没有跟着变。

A3 把核也按 s 缩放（7·s 取奇数、下限 3：s=0.65 与 0.5 用 5，s=0.4 以下用 3），结果是 s=0.5 / 0.4 / 0.3 全部回满分，s=0.22 时 F1 0.981（开花 0.993、花苞 0.908）。s=0.22 剩下的损失也讲得清：7×0.22≈1.5，下限把核卡在 3，仍是理论值的约两倍；且此时花苞半径只剩 2.4 至 3.7 px，轮廓本身已在像素离散化的噪声里。

### 3.3 面积本身也不严格按 s² 走：越小的目标缩得越多

把匹配到的轮廓面积中位数除以 s² 预测（即与基线中位数×s² 相比），得到的是系统性偏小，而且目标越小偏得越多：

| s | 开花面积比（实测/预测） | 花苞面积比 | 花苞可匹配轮廓数 |
|---|---|---|---|
| 0.8 | 0.986 | 0.960 | 76/76 |
| 0.65 | 0.983 | 0.912 | 76/76 |
| 0.5 | 0.960 | 0.809 | 76/76 |
| 0.4 | 0.950 | 0.673 | 44/76 |
| 0.3 | 0.925 | —（仅剩 1 个） | 1/76 |
| 0.22 | 0.896 | —（无） | 0/76 |

开花从 -1.4% 一路漂到 -10.4%，花苞在还能测的范围内漂到 -32.7%。两个来源：一是重采样与颜色阈值的作用面在边缘，目标周长与面积之比越大，边缘蚀失占比越高，小目标吃亏；二是形态学开运算对小掩膜的相对侵蚀更强。后半段的花苞数字有幸存者偏差——能匹配到的已经是同类里偏大的那些，真实漂移只会比表里更狠，s=0.3 以下干脆没有样本可测。结论收在本管线的边界内：对颜色阈值加形态学这类以绝对面积分类的管线，s² 是面积标定的一阶近似，不是精确律；按它缩放阈值时，分类门槛附近的临界目标会系统性地偏向小类一侧，距离越远偏得越多。换了分割方式（自适应阈值、边缘保留滤波、学习型检测器）的管线，漂移的方向和量级都可能不同，本文没有测。

### 3.4 分辨率退化（先缩再放回）：几何不变，阈值基本不用动

B 组的结果和 A 组像两个世界。有效像素一路降到 160×120（r=0.125，像素数只剩 1/64）再放大回原尺寸，固定参数的 F1 是 0.995，全程只丢 2 个目标（开花、花苞各一）；r=0.167 时 F1 0.998，r≥0.25 全部满分。每档扫 `bloom_area_min` 倍率，最优点始终在 1.0 倍——没有重标的必要。

面积漂移的方向也和 A 组不同：开花轮廓面积中位数不降反升，r=0.125 时为基线的 1.096 倍；花苞则降到 0.854 倍。低通式的模糊把大目标的花瓣碎片连成更整的一片（闭运算又顺手搭桥），把小目标的边缘吃掉一圈，两个方向同时发生。但只要图像最终以同样的像素尺寸送进检测器，两类面积仍稳稳分居 900 两侧，分类不受影响。

把两组并排，结论就清楚了：决定阈值是否作数的，是目标在检测器输入图上的像素尺寸，不是传感器标称分辨率。在取景不变（同一视场、同一构图）的前提下，一台相机若把画面放大到同一输入尺寸出图，就阈值几何这一层近似 B 组；若以原生小尺寸帧直接喂检测器，那就是 A 组，分辨率和距离在数学上是同一件事。把边界说清：B 组建模的只是数字重采样链（面积平均下采样加双线性上采样，本质是低通平滑），真实低分辨率传感器还有像元混叠、Bayer 解马赛克与镜头点扩散的退化，本文没测，那些退化会不会另外咬到颜色分割，不在本文结论内。现场说「换了相机要重标」，先要问清是哪一种接法。

## 4. 分析与取舍

四条可直接拿走的：

1. 重标要标全套，不只标分类门槛。一条管线里所有以像素写死的参数都有量纲：面积类按 s² 缩（分类门槛、最小面积），长度类按 s 缩（形态学核、匹配容差、最小间距、NMS 半径之类）。失效的先后顺序不取决于参数在代码里的执行次序（形态学明明跑在最前面），而取决于每个参数的取值与它所管的那批目标尺寸的比值：目标整体等比缩小时，谁先与自己所辖目标的尺寸相撞，谁先失效。本文这批目标里花苞比开花小一个量级，所以顺序是 `min_area` 先撞上花苞、分类门槛再撞上开花、核最后才涨到花苞短轴的量级；换一个目标尺寸分布完全不同的场景，顺序会变，但「按比值撞线」的判法不变。只改最显眼的那个分类门槛，是这条管线在 s=0.4 时 F1 停在 0.915 的原因。这条缩放处方也有它的适用下限：目标还剩数个像素见方、核还能取到 3 以上的奇数时才成立；再往下，像素离散化本身成了主导因素（s=0.22 的残余损失就是），缩放律救不回来，只能换机位或换检测方法。
2. 判断卡点的方法比结论本身可复用：在其他参数已逐个排除后，某个参数扫遍合理区间、指标进入平台（本文 s≤0.3 时变化不超过 0.006），瓶颈就不在这个参数上，丢失发生在它的上游或下游。本文靠这条把锅从阈值挪到了核上；上一篇靠同样的办法分辨过预处理与遮挡的边界。3. 部署侧的标定动作可以做成一条估计式，不必每换机位就重跑全套标定：先在新机位拍几帧，量出开花轮廓面积中位数，与基准中位数之比开根号就是 s 的估计，再按上一条全套缩放。本文没有单独验证这条估计式的端到端精度（实验里 s 是重采样给定的真值、不是估出来的），它只能算由本文数据支撑的候选做法，列在这里供复核，不算结论。
4. 监控盯最小类。本文所有崩坏都是花苞先死、开花后伤，距离组如此，上一篇的光照与遮挡组也是如此。按类别分开记召回、给最小类单独设报警线，比盯总数能早一到两个阶段发现标定漂移。

取舍上还有一个没选的方案值得记一句：把检测器输入统一重采样到基准尺寸（小图先放大再检测），等价于把缩放从参数侧挪到图像侧。本文 B 组说明图像侧放大本身不伤分类，但它救不了 A 组那种原生小图里已经不存在的高频信息——放大回来的花苞短轴仍是糊的，核与阈值面对的仍是退化后的掩膜。所以两条路不是等价的：参数缩放保的是已到手的像素，输入重采样改变的是参数面对的像素构成。本文选参数缩放作主结论，输入重采样的对照没有系统跑，列为未测。

## 5. 局限与未解问题

- 全部场景仍是模拟图，且缩放是数字重采样：INTER_AREA 是特定的盒式滤波近似，不等于真实镜头的点扩散与传感器采样，更没有建模低分辨率传感器的像元混叠与 Bayer 解马赛克退化；真实后退一倍距离还会同时改变透视、景深与光照角度，本文只隔离了几何缩放这一个变量。数字是这条管线在纯缩放下的漂移规律，不能直接当真实机位迁移的精度承诺。
- 只测了变远（s<1），没有测凑近（s>1）：按对称性预测凑近时面积阈值相对变松、核相对变细，主要风险换成大目标出框与重叠粘连，但这是预测、未实测。
- s 由重采样给定，是真值；现场估计 s 要靠参照物尺寸或面积中位数反推，估计误差会直接传进三个参数，本文未测这条误差链。
- 核缩放的取整规则（7·s 取奇数、下限 3）是本文的工程选择，不是唯一解；s=0.22 档核被下限卡在理论值的两倍，该档残余损失里有多少来自取整、多少来自像素离散，分不开。
- 花苞面积漂移在 s≤0.3 后没有样本（轮廓已被核抹除），漂移曲线的小目标段是断的；s=0.4 档的 -32.7% 本身带幸存者偏差，真实值更低。
- B 组只测了一种退化链（INTER_AREA 下采样加 INTER_LINEAR 上采样）；换插值算法、加 JPEG 压缩或传感器噪声，面积漂移的方向与量级可能变化。
- 场景仍只有 4 张、210 个目标，同一模拟器同一检测器；结论对「面积阈值加形态学」这一类管线的迁移性是推理，不是实测过的跨管线验证。
