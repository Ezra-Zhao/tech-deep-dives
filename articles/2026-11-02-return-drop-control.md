# 丢在回程，账一分不少：回程丢弃对照实测——端到端代数等价，分解账形态翻转

作者：Guangyi Zhao

## 1. 问题与背景

这个系列里有两笔账一直挂着同一句话：垫片只丢去程，回程没测。

第一笔在 2026-10-28 那篇。我在 net-assurance-lab 的服务器侧加了一级额外丢弃垫片，量注入带告警（端到端总丢包大于 0.75）的判别力：额外丢弃的概率 q 到约 0.47 才报警。那篇第 5 节写明：垫片丢的是客户端到服务器方向的请求，模拟「服务器在收包环节丢弃」；若真实故障丢的是服务器的回程答复，端到端代数相同（存活率连乘），但分解账的形态不同，没有实跑对照。

第二笔在 2026-11-01 那篇。我把总丢包拆开，用 exporter 已发布的五个数重构出段丢弃率 D（代理去程放行之后、回程进入代理之前这一整段的丢弃率），它的检出临界约 0.10、读数就是那一段丢了多少。但那篇同样写明：D 对回程方向的段丢弃是盲是感，没有实测——按计数点位置推，回程丢弃会抬高 D 并被记在整段账上，这是推理，不是实测。

这篇把垫片翻个方向，其余一个字不改：去程原样放行，服务器把每个回程答复以概率 q 丢掉。三个问题，按预注册的顺序：端到端丢包与 0.75 规则的检出临界是否与去程丢弃等价；D 是否照样读出回程的丢弃率；分解账的形态到底怎么变。先说结论：等价的部分比预想的干净——隔离口径下 0.75 规则的触发形态逐档与去程轮相同（q=0.40 时 0/4、0.50 起 4/4），D 与垫片回程实测丢弃率在 28 轮里逐轮逐位相等；翻转的部分也比预想的彻底——段内拆分量 D_srv 与 D_ret 的取值整个对调，去程轮里 D 全部落在去程子段（D_ret 逐轮恰为 0），回程轮里全部落在回程子段（D_srv 逐轮恰为 0）。两条规则本身都分不出方向，能分方向的是服务器计数：回程轮里服务器把活全干完了才丢包，q=0.60 档每轮平均白回了 3,908 个包。

还有一笔跨轮差异要在正文里当场说清，免得读者拿两篇的表直接相减得出错误结论：回程轮中段各档的端到端丢包比去程轮存档低 1.2 到 3.5 个点。这不是方向效应，证据在 3.4 节——去程轮那批数据带着它自己已记录在案的台架负载混杂，而回程轮这一批 28 轮台架缺口全为零。方向受控的量（D、段内拆分、隔离口径触发形态）逐项对齐，不受控的总丢包均值不许跨天相减，这正是这个系列从 2026-10-28 起坚持双口径报告的原因。

## 2. 方法

预注册在跑分前冻结落盘（data/2026-11-02-return-drop-prereg.md），含对照设置、六个量法定义与五条预测 P1 至 P5，跑完不许挪线。

- 链路与参数：traffic_gen 到 fault_proxy 到回程丢弃垫片到 echo_server，全在本机回环。注入参数逐字不变——loss 0.20 双向、delay 40 ms、jitter 30 ms、flap 0.6/2.5、代理种子 1234；流量 sustained 2000 pps 乘 5 秒共 10,000 个包。与 2026-10-28 去程轮的唯一差别是垫片方向。
- 回程垫片（data/2026-11-02-return-drop-shim.py）：去程收到什么转发什么；回程每收到一个服务器回显，以概率 q 丢弃并计数，其余转发回代理。种子基数 42000，与去程轮的 20000、分解感知留出轮的 31000 不重叠。q 网格与去程轮相同：0、0.10、0.20、0.30、0.40、0.50、0.60，每档 4 次共 28 轮，端口逐轮轮换。
- 判定走 exporter 真链路：每轮产物推过 prom_exporter 的 collect()，两条规则与全部读数都从它输出的 exposition 文本里解析（sent、echoed、代理的 in_client/in_server/forwarded、服务器的 received_total/echoed），即 Prometheus 实际会抓到的那个对象。原始日志只用来验恒等式与归因。
- 量法（预注册冻结）：L 为部署口径总丢包，L_iso 为以代理 in_client 为分母的隔离口径；OLD 为 L 或 L_iso 大于 0.75；F_c 等于 forwarded 减 echoed（2026-11-01 篇的重构式）；D 等于 1 减 in_server 除以 F_c，CAND 沿用冻结线 D 大于 0.10。本轮新增段内拆分：D_srv 等于 1 减 server_received 除以 F_c（去程子段），D_ret 等于 1 减 in_server 除以 server_echoed（回程子段）；代数上 (1-D) 等于 (1-D_srv) 乘 (1-D_ret)，三量不独立。去程基线取自 2026-10-28 存档的 28 轮原始记录，本轮跑分前已用同一组公式复算：其 D_srv 与 D 逐轮相等、D_ret 逐轮恰为 0.0000（28/28）。

## 3. 实测数据

### 3.1 恒等式与台架状态：这一批 28 轮干净得罕见

六项重构恒等式（F_c 等于代理去程放行计数、echoed 等于代理回程放行计数、代理 in_server 等于垫片回程放行数、服务器收数等于垫片去程放行数、垫片回程入数等于服务器回显数、服务器原始计数与 exporter 发布值一致）在 28 轮里逐轮全部成立，28/28；exporter 丢包率与发生器汇总逐轮全等，28/28。四跳缺口（代理到垫片、垫片到服务器、服务器到垫片、垫片到代理）逐轮全为 0，发生器到代理的台架缺口也逐轮为 0——in_client 每轮都是完整的 10,000。这与去程轮形成对照：那一批缺口最高 29.8%、段内还出现过一次 145 个包的跳间缺口。本轮的干净是后面几节敢说「逐位相等」的前提，也是 3.4 节归因的依据；它不保证下一批还这么干净，局限节会回到这一点。

OLD 在隔离口径下的结论完整复现：q 到 0.40 仍全哑、0.50 起全响，检出临界约 0.47 不因丢弃方向移动（P2 命中）。部署口径本轮与隔离口径相同；去程轮部署口径曾在 q=0.20、0.30、0.40 出现 1/4、1/4、3/4 的提前触发，2026-10-28 篇已逐轮归因为台架缺口顶线，本轮缺口为零所以没有这个现象——这是台架状态差异，不进方向结论。

CAND 只有一个档位需要单独说：q=0.10 是预注册里写明的临界档、不预言方向。回程轮四轮 D 为 0.1014 到 0.1049，全部刚刚越线，触发 4/4；去程轮四轮 D 为 0.0928 到 0.1227、三轮在线下、一轮在线上（且那一轮正是 145 个包跳间缺口的那一轮），触发 1/4。但两轮 D 均值只差 0.0004（0.1027 对 0.1031）；垫片在入数约 6,100 时 q=0.10 的单轮抽样标准差约 0.0038，回程轮四轮均值离名义值 0.0027、约为该标准差的 0.7 倍，单轮最大偏差 0.0049 也在 1.3 个标准差内。临界档的触发计数是掷硬币，读数本身才作数，两轮读数一致——这一档两边都只能报到这里。

### 3.3 D 读回程：逐位相等，拆分整个翻转

以垫片回程实测丢弃率（dropped_extra 除以 in_server_shim，它是真值、不进规则）为对照：28 轮里 D 与它的差，中位数为 0.0、最大值约 1e-16，即每一轮都精确相等（P3 命中，CAND 在 q 不小于 0.20 各档 4/4、q=0 档 0/4）。对名义 q 的口径：D 均值与 q 的差在各档为 -0.0022 到 +0.0030，与去程轮同量级，那是垫片伯努利抽样自身的散布，不是读数误差。

段内拆分翻转得没有任何含糊（P4 命中）：

- 回程轮：D_srv 每一档均值都是 0.0000（逐轮为 0），D_ret 等于 D（逐轮相等，均值从 0.1027 到 0.5978 贴着 q 走，对名义 q 的全网格误差中位数 0.0035）。
- 去程轮（存档复算）：D_ret 每一轮恰为 0.0000，D_srv 等于 D。
- 拆分恒等式 (1-D) 等于 (1-D_srv) 乘 (1-D_ret) 在回程轮 28 轮的最大偏差为 0——因为每轮总有一侧子段恰为零且四跳无缺口，这个等式在本轮是以计数相等的形式成立的，不是近似。

也就是说，2026-11-01 篇留下的推理——回程丢弃会抬高 D 并记在整段账上——实测成立，而且比推理多走了一步：D 不仅感得到回程丢弃，它的段内拆分还能把丢弃定位到子段，前提是服务器计数可用。exporter 本来就发布服务器计数（nal_server_packets_total），所以拆分和 D 一样，不需要改 exporter。

### 3.4 为什么回程轮的总丢包均值更低：不是方向，是去程轮的负载

把两轮的 L_iso 均值相减，中段差出 +2.9（q=0.10）、+3.5（0.20）、+2.5（0.30）、+1.6（0.40）、+1.2（0.50）、+0.4（0.60）个点，去程更高。若不加解释，这看起来像方向效应。三条证据说明它不是：

第一，锚点对齐。两轮 q=0 的注入基线几乎相同：L_iso 均值 0.5265 对 0.5280，去程抖动份额 23.99% 对 23.97%，回程抖动份额 3.06% 对 3.30%，随机丢弃份额也同量级。台架安静时两轮测出的注入带是同一个带。

第二，代数自洽。隔离口径下端到端存活率应当等于基线存活率乘段存活率，即 L_iso 预测值等于 1 减 (1 减 q=0 基线) 乘 (1 减 D 均值)。回程轮用自身基线代入，各档预测与实测的差为 -0.0002 到 -0.0030，全在 0.3 个点内；去程轮用自身基线代入同样的式子，中段却系统性高出 +2.8、+3.2、+2.4 个点（q=0.10 到 0.30），向两端收敛。这个偏差不是这篇新发现的——2026-10-28 篇 3.3 节已经记下「活体隔离均值在中段比模型高 1 到 3 个点」并归因于负载抬高注入基线，当时合并统计的去程抖动份额在重负载轮涨到了 26.96%。

第三，份额账对得上。本轮事后复算：去程轮全部 28 轮合并的去程抖动份额是 26.96%、回程抖动份额 4.57%，而其 q=0 四轮单独算是 23.97% 与 3.30%——高出的部分集中在它那些带台架缺口的重负载轮。回程轮全部 28 轮合并是 23.99% 与 2.99%，与其 q=0 锚点（23.99% 与 3.06%）基本重合，整批都处在安静状态。

结论：方向对端到端代数没有可测的影响（代数预测在干净台架上准到 0.3 个点内）；跨轮均值差来自去程轮的负载混杂，它的量级（中段约 3 个点）也给出一个实用提醒——拿不同日子的活体均值直接相减，先查两批的台架状态，否则会把负载读成机制。

### 3.5 服务器白工：回程轮每轮多回约四千个包

形态翻转里最有运维意味的是服务器计数本身（P5 命中）。回程轮里服务器收包数与回显数逐轮恰等于 F_c（28/28，server_echoed 与 F_c 逐轮全等）：去程子段一包不丢，服务器对每个活过注入的请求都生成了回显，然后其中 q 的比例死在回程垫片上。去程轮里服务器只收到垫片放行的那部分，q=0.60 档回显均值 2,207 个；回程轮同档是 6,115 个，差 3,908 个，约当该档 F_c 均值的 64%。换句话说，同样的端到端丢包读数、同样的 D，去程故障里服务器只干了四成活，回程故障里服务器干了全部的活再被丢掉六成——告警账上一模一样，成本账上完全两样。本实验台的 echo 服务器成本可以忽略，这里的 3,908 是包数不是钱；但把这个形态搬到真实服务上，请求处理与响应生成已经花掉的算力、以及回程链路已经占用的带宽，都属于回程丢弃独有的浪费，这部分是推理、不是本轮实测，只记方向不记量级。

### 3.6 预注册对账

P1（q=0 锚点：L 均值落在去程 0.5315 的正负 0.02 内、D 全不大于 0.03）命中，实测均值 0.5265、四轮 D 全为 0。P2（OLD 隔离口径 0.40 时 0/4、0.50 与 0.60 时 4/4）命中，逐档与去程相同。P3（D 对垫片回程实测的中位误差不大于 0.02；CAND 在 q 不小于 0.20 各档 4/4、q=0 时 0/4）命中且强于预测——中位误差为 0.0、逐轮逐位相等。P4（D_srv 各档均值不大于 0.03、D_ret 对 q 的中位误差不大于 0.02，与去程镜像）命中，D_srv 逐轮为 0、中位误差 0.0035。P5（server_echoed 约等于 F_c；q=0.60 档两方向回显均值差不小于 F_c 均值的 40%）命中，差为约 64%。五条全中；唯一事先声明不预言方向的 q=0.10 临界档，落点为回程 4/4、去程 1/4，读数均值一致，已在 3.2 节单独交代。

## 4. 分析与取舍

把三篇的账连起来看，分解感知这套读法到今天算是闭环了：总丢包（OLD）回答「有没有超出注入的丢包」，临界约 0.47、方向盲、台架敏感；整段率 D 回答「代理两个计数点之间那一段丢了多少」，临界约 0.10、对台架缺口免疫（2026-11-01 篇 A 层证据）、对段内方向盲；段内拆分 D_srv 与 D_ret 回答「丢在去程子段还是回程子段」，本轮证明它在服务器计数可用时成立，且与 D 同源、同样不需要改 exporter。三层各答一个问题，合起来才是完整的定位：响、丢多少、丢在哪个方向。

方向这个信息值不值得单独拆，取决于故障处置路径。去程丢弃指向收包侧（服务器入口、入向链路、接收队列），回程丢弃指向回包侧；两者在端到端监控上长得一模一样（本轮 L 与 D 逐档对齐到读数级），不拆就只能靠登录服务器看计数——而拆分的全部输入（代理 in_server、forwarded、echoed 与服务器 received、echoed）已经在 exporter 里现成发布。我的判断（工程判断，证据等级 B）：凡是已经部署了 D 的场景，顺手把 D_srv 与 D_ret 一并算出来几乎没有成本，不加才是浪费；判定线怎么定不在本轮范围内，D_srv 与 D_ret 各自的噪声基线目前只有本轮与去程轮两个干净到近乎极端的样本（一个逐轮为零、一个带过一次 0.024 的缺口事件），拿这点样本定线为时过早。

另有一个方法论层面的收获，比结论本身更值得留下来：这次对照之所以能把「方向」和「负载」分开，靠的是两轮各有自己的 q=0 锚点与逐轮分解账，而不是靠均值表。去程轮的负载混杂在它发表时就被分解账抓到并写进了局限，所以今天的跨轮比较有账可查、能定量归因（抖动份额 26.96% 对 23.99%）；若当时只报均值，这篇的第一个结论就会被误读成方向效应。分解账不是给结论做装饰，它是给下一篇留的对照组。

## 5. 局限与未解问题

- 「逐位相等」是这一批台架的属性，不是方法的属性。本轮四跳缺口逐轮为零纯属这台主机这段时间安静；去程轮里一次 145 个包的跳间缺口就把 D 与垫片真值的差推到了 0.0239。段内拆分同理：子段之间任何一跳出现缺口，它会被记进相邻子段的账，拆分精度随缺口大小退化。本轮证明的是恒等式与读法成立，不是任何环境下都精确。
- 跨轮比较终究不如同场交错：两轮隔了五天、台架状态不同，方向等价的结论靠锚点加代数自洽加份额归因三条腿支撑，没有做同一次会话内去程与回程交替跑的 A/B 对照。那个对照能把负载混杂从设计上消掉，是这组实验还欠的最干净的一笔。
- 双方向同时丢弃没有测：若去程与回程子段同时以非零概率丢弃，拆分恒等式在代数上仍给出 D_srv 与 D_ret 两个可分离的读数（计数点是串联的），但两级伯努利抽样的相互影响与缺口污染的叠加没有实测，本轮的镜像形态（总有一侧恰为零）恰恰是最容易的情形。
- 服务器成本只量到包数：echo 服务器的回显成本近乎为零，3,908 个白回的包在本实验台不构成任何真实成本陈述；真实服务里请求处理与响应生成的成本结构完全不同，回程丢弃的浪费量级要按具体服务另测，不能搬运本轮数字。
- 每档仍只有 4 次重复，触发率的分辨粒度是 25 个点；临界档（q=0.10）附近的触发计数两轮不一致（4/4 与 1/4）正是这个粒度下的预期行为，本轮以读数均值与分布位置代替计数下结论，这个处理在加密网格（q 取 0.05 到 0.20 细档）面前仍值得复验。
- D_srv 与 D_ret 的判定线未定（见第 4 节）：两条子段率的噪声基线样本太少，本轮只证明可读、不给线上阈值，部署时先以记录模式跑一段再定线。
